# Data Model: Frontend ↔ Backend Integration of the Todo App

## Todo Entity

### Attributes
- **id**: Unique identifier (string/number, auto-generated by backend)
- **title**: Task title/description (string, required)
- **completed**: Completion status (boolean, default: false)
- **createdAt**: Creation timestamp (datetime, auto-generated by backend)
- **updatedAt**: Last update timestamp (datetime, auto-generated by backend)

### Validation Rules
- **title**: Must be non-empty string with 1-255 characters
- **completed**: Boolean value only (true/false)
- **id**: Must be unique within the system

## API Response Structure

### Success Response
```json
{
  "success": true,
  "data": { /* entity data */ },
  "message": "optional message"
}
```

### Error Response
```json
{
  "success": false,
  "error": {
    "code": "error_code",
    "message": "human-readable message",
    "details": { /* validation errors or additional info */ }
  }
}
```

## State Transitions

### Todo Lifecycle
1. **Created**: New todo added to system (completed: false)
2. **Updated**: Todo properties modified (title, completed status)
3. **Deleted**: Todo removed from system

### Status Changes
- **Active** → **Completed**: When user marks todo as done
- **Completed** → **Active**: When user unmarks completed todo
