## Entities

### User (managed by Better Auth via Drizzle)

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | `text` | PK | UUID generated by Better Auth |
| `name` | `text` | NOT NULL | User display name (FR-001) |
| `email` | `text` | NOT NULL, UNIQUE | User email address (FR-002) |
| `emailVerified` | `boolean` | NOT NULL, default `false` | Email verification status |
| `image` | `text` | NULLABLE | Profile image URL (unused in this phase) |
| `createdAt` | `timestamp` | NOT NULL | Account creation time |
| `updatedAt` | `timestamp` | NOT NULL | Last update time |

**Validation Rules**:
- `email`: RFC 5322 compliant, unique per account (FR-002)
- `name`: Required, non-empty (FR-001)
- Password: minimum 8 characters (FR-003) — stored in `account` table, not `user`

**Notes**: Better Auth generates UUIDs for `id`. The password is stored in the `account` table (hashed), not in the `user` table directly.

---

### Session (managed by Better Auth via Drizzle)

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | `text` | PK | Session identifier |
| `token` | `text` | NOT NULL, UNIQUE | Session token value |
| `userId` | `text` | NOT NULL, FK → `user.id` | Associated user |
| `expiresAt` | `timestamp` | NOT NULL | Session expiration time |
| `ipAddress` | `text` | NULLABLE | Client IP address |
| `userAgent` | `text` | NULLABLE | Client user agent string |

**Lifecycle**:
- Created on successful sign-in (FR-005, FR-006)
- Deleted on sign-out (FR-013)
- Checked on session queries (`getSession`)

---

### Account (managed by Better Auth via Drizzle)

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | `text` | PK | Account identifier |
| `userId` | `text` | NOT NULL, FK → `user.id` | Associated user |
| `accountId` | `text` | NOT NULL | Provider-specific account ID |
| `providerId` | `text` | NOT NULL | Auth provider (`"credential"` for email/password) |
| `accessToken` | `text` | NULLABLE | OAuth access token (unused) |
| `refreshToken` | `text` | NULLABLE | OAuth refresh token (unused) |
| `accessTokenExpiresAt` | `timestamp` | NULLABLE | Token expiry (unused) |
| `refreshTokenExpiresAt` | `timestamp` | NULLABLE | Token expiry (unused) |
| `scope` | `text` | NULLABLE | OAuth scope (unused) |
| `password` | `text` | NULLABLE | Hashed password (FR-004) |
| `createdAt` | `timestamp` | NOT NULL | Account creation time |
| `updatedAt` | `timestamp` | NOT NULL | Last update time |

**Notes**: For email/password auth, `providerId` = `"credential"`, `accountId` = `user.id`, and `password` stores the bcrypt/argon2 hash. OAuth fields are unused in this phase.

---

### JWKS (managed by Better Auth JWT plugin via Drizzle)

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | `text` | PK | Key ID (`kid` in JWT header) |
| `publicKey` | `text` | NOT NULL | Public key component |
| `privateKey` | `text` | NOT NULL | Private key (encrypted with AES-256-GCM by default) |
| `createdAt` | `timestamp` | NOT NULL | Key creation time |
| `expiresAt` | `timestamp` | NULLABLE | Key expiry (for rotation) |

**Lifecycle**:
- Auto-created by JWT plugin on first token request
- Exposed via `GET /api/auth/jwks` (public keys only)
- Old keys retained during grace period after rotation

### Todo (managed by FastAPI via SQLModel) — MODIFIED

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | `integer` | PK, auto-increment | Task identifier |
| `title` | `varchar(255)` | NOT NULL, min 1 char | Task title |
| `description` | `varchar(1000)` | NULLABLE | Task description |
| `completed` | `boolean` | NOT NULL, default `false` | Completion status |
| `user_id` | `text` | NOT NULL | **NEW**: Owner's user ID (matches `user.id`) (FR-017) |
| `created_at` | `timestamp` | NOT NULL | Creation time |
| `updated_at` | `timestamp` | NOT NULL | Last update time |

**Changes from existing model**:
- Added `user_id` field (`text`, NOT NULL) — stores the Better Auth user UUID
- All queries now filter by `user_id` (FR-009)
- No database-level foreign key constraint (cross-ORM boundary); enforced at application level

**Validation Rules**:
- `title`: 1–255 characters, required
- `description`: 0–1000 characters, optional
- `user_id`: Must match the authenticated user's JWT `sub` claim (FR-010)

### Authentication Token (ephemeral — not stored in DB)

| Claim | Type | Source | Description |
|-------|------|--------|-------------|
| `sub` | `string` | `user.id` | Subject — the user's UUID |
| `id` | `string` | `user.id` | User ID (redundant with `sub`) |
| `email` | `string` | `user.email` | User's email address |
| `name` | `string` | `user.name` | User's display name |
| `iss` | `string` | `BETTER_AUTH_URL` | Issuer |
| `aud` | `string` | `BETTER_AUTH_URL` | Audience |
| `exp` | `number` | `now + 3600` | Expiry (1 hour) |
| `iat` | `number` | `now` | Issued at |

**Notes**: JWT is signed with EdDSA (Ed25519). The `kid` header references the key in the `jwks` table. Verified by the backend via JWKS endpoint.

## State Transitions

### User Lifecycle
```
[Visitor] → sign-up → [Registered User] → sign-in → [Authenticated User]
                                                   → sign-out → [Registered User]
                                                   → token expires → [Registered User]
```

### Session Lifecycle
```
[None] → sign-in → [Active Session] → sign-out → [None]
                                     → expires → [None]
```

### Token Lifecycle
```
[None] → authClient.token() → [Valid JWT] → API request → [Verified by backend]
                                           → expires → [Rejected by backend (401)]
                                           → tampered → [Rejected by backend (401)]
```

## Schema Migration Notes

### Better Auth tables (frontend, Drizzle)
```bash
# Generate schema from Better Auth config
npx @better-auth/cli@latest generate

# Generate SQL migration files
npx drizzle-kit generate

# Apply to Neon database
npx drizzle-kit migrate
```

### Todo table (backend, SQLModel)
```python
# Auto-creates/updates on startup
SQLModel.metadata.create_all(bind=engine)
```

The `user_id` column will be added to the existing `todo` table. Since this is a development database, the simplest approach is to drop and recreate the table, or add the column with a migration query. SQLModel's `create_all` will add the table if it doesn't exist but won't alter an existing table — a manual `ALTER TABLE todo ADD COLUMN user_id TEXT NOT NULL DEFAULT ''` may be needed if the table already exists with data.
